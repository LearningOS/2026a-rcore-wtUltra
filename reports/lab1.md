# lab1：多道程序、时间与 trace

实验日期：2026-10-26（Asia/Shanghai）。对应章节：ch3。

## 功能总结（200 字以内）

实现 trace 的单字节读写、按任务隔离的系统调用计数和无效请求拒绝。统一在系统调用分发前计数，使 trace 查询包含本次调用；计数和调度状态不跨切换持有借用。沿用原有时间与轮转调度，使用真实 QEMU 运行官方测例。

## 实现与边界

- 计数键为任务编号与系统调用编号，稀疏表避免在内核栈构造大尺寸数组。
- 请求 0 返回一个字节；请求 1 只写低 8 位；请求 2 查询当前任务计数；其他请求返回 -1。
- 本章共用地址空间，题目未要求验证读写地址；下一章引入用户权限校验。

## 问答

### 1. U 态特权访问与故障

U 态不能执行 `sret`，不能读取 `sstatus` 等 S 态 CSR。官方 `ch2b_bad_address` 写地址 0，触发 StoreFault；内核将 StoreFault/StorePageFault 共用的提示打印成 `PageFault ... bad addr = 0x0`，但本章未启用 Sv39，不能据此把本次访问故障说成页表缺页，也不能宣称所有内核物理地址已经隔离。另两个程序执行 `sret` 或读取 `sstatus`，实测均打印 `IllegalInstruction`。trap 处理器终止出错任务并调度其他任务，而不是允许其越权继续执行。使用仓库固定的 RustSBI 0.4.1；具体现象以附带的原始运行日志为准。

### 2. `__alltraps` 与 `__restore`

1. 刚进入 `__restore` 时，sp 指向内核栈上的 TrapContext。它既用于首次启动任务、构造上下文后进入 U 态，也用于处理异常/系统调用/时钟后恢复原任务。
2. `32*8(sp)` 与 `33*8(sp)` 分别保存 sstatus 和 sepc；`2*8(sp)` 是用户 sp。恢复 sstatus 中的 SPP/SPIE 等字段，恢复用户返回 PC，并将用户 sp 暂存在 sscratch。
3. x2 即 sp，不能在恢复其余寄存器之前覆盖内核上下文地址，最后通过交换恢复；x4 即 tp，在本框架未供用户程序使用，故省略，不能据此推断所有操作系统都可以不保存 tp。
4. 恢复末尾交换后，sp 是用户栈指针，sscratch 是内核栈顶，供下一次 trap 交换使用。
5. `sret` 是特权级实际切换指令：SPP 被预置为 U，PC 从 sepc 恢复，并按特权规范恢复中断状态。
6. 进入 `__alltraps` 后的首次交换让 sp 获得内核栈顶、sscratch 暂存用户 sp，随后才能在内核栈保存寄存器。
7. U 到 S 的切换不是在 `csrrw` 中发生：`ecall`、非法指令或时钟等事件触发硬件 trap 入口，在执行 stvec 指定的入口指令前，处理器已切换至 S 态。
