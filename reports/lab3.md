# lab3：进程创建与 stride 调度

实验日期：2026-10-26
对应章节：ch5

## 功能总结

本次实验将前序章节的 `sys_get_time`、`sys_mmap` 和 `sys_munmap` 迁移适配到了本章的进程控制块架构上，并实现了 `sys_spawn` 系统调用与 Stride 调度算法。`spawn` 直接从目标 ELF 文件构造子进程地址空间、建立父子关系并加入调度队列，避免了 `fork` 拷贝父进程地址空间的开销。同时实现了 `sys_set_priority` 接口与按最小 stride 选择进程的调度器，采用宽整数保存虚拟运行时间，完整保留了 `fork`/`exec`/`waitpid` 生命周期。

## 实现细节与踩坑记录

- **优先级与步长计算**：进程初始默认优先级权重设为 `16`，当 `sys_set_priority` 传入小于 `2` 的参数时直接返回 `-1`。每次调度选中进程时，其 stride 增加 `max(2^64 / priority, 1)`，并使用 `u128` 宽整数存储虚拟运行量，从而在实际运行周期内彻底避免窄位宽快速回绕的问题。
- **子进程初始状态**：`fork` 出的子进程直接继承父进程的优先级权重与当前虚拟运行量；`spawn` 创建的子进程则使用默认权重 `16`，但以父进程当前的虚拟运行位置作为初始 stride，防止新建进程凭借 `stride = 0` 的历史零值长期抢占 CPU。
- **就绪队列选择**：针对实验规模，就绪队列采用线性扫描挑出当前 stride 最小的进程投入运行，逻辑直观且易于排查并发问题。

## 问答题：stride 的回绕

1. **无符号普通比较的问题**：若使用 8 位无符号整数 `u8` 并直接按普通无符号大小比较，当进程 `p2` 的 stride 从 `250` 加上步长 `10` 后会溢出回绕变成 `4`。下一次调度时，调度器会因为 `4 < 255` 而错误地继续选中 `p2`，但从真实的虚拟时间来看应当判定 `255 < 260`。
2. **差值不超过半圈（B/2）的保持条件**：在所有进程初始值一致、持续保持就绪状态、每次只给当前最小 stride 的进程增加步长，且单次步长不超过 `B/2` 的前提下：假设调度前所有进程的 stride 区间宽度至多为 `B/2`，那么将最小值加上一个不超过 `B/2` 的步长后，得到的新值最大也不会超过“旧最小值 + B/2”，而其余进程的值均未改变，因此所有进程间的最大差值依然保持在 `B/2` 以内。需要注意，若存在任意睡眠后被唤醒或新建进程初始 stride 不受约束的情况，该结论不能直接套用。
3. **基于环状差值的比较器实现**：当模空间内任意两个 stride 的真实距离小于半圈时，可以将 `self.0.wrapping_sub(other.0) as i64` 的符号作为两者的逻辑差值。由于 Rust 标准库的 `BinaryHeap` 默认是最大堆（弹出最大值），为了每次弹出逻辑上最小的 stride，需要将比较顺序反转：

```rust
use core::cmp::Ordering;

struct Stride(u64);

impl PartialOrd for Stride {
    fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
        Some(0i64.cmp(&(self.0.wrapping_sub(other.0) as i64)))
    }
}

impl PartialEq for Stride {
    fn eq(&self, other: &Self) -> bool {
        self.0 == other.0
    }
}
```

这样在最大堆中，逻辑上最小的 stride 会被判定为“最大项”从而位于堆顶。在实际内核实现中，为了避免半圈边界歧义，我直接采用了 `u128` 宽整数来规避回绕。
